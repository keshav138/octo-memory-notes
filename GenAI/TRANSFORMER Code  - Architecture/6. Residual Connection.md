```python
class ResidualConnections(nn.Module):
    def __init__(self, dropout: float):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        self.norm = LayerNormalization()
    
    def forward(self, x, sublayer):
       return x + self.dropout(sublayer(self.norm(x))) 
```

This class is actually much simpler than Multi-Head Attention, but it can look confusing because of one thing:

```python
sublayer(self.norm(x))
```

The `sublayer` isn't a fixed function—it's passed in as an argument. Let's build up to that.

---

# First, what is a Residual Connection?

Suppose you're trying to learn something difficult.

Instead of saying

```text
Input

↓

Completely new output
```

the transformer says

```text
Input

↓

Small modification

↓

Add it back to the original input
```

Instead of learning

```text
Output
```

the network only learns

```text
Difference
```

or

```text
Correction
```

This is much easier for deep networks.

---

# Without residuals

```text
Input
   │
   ▼

   │
   ▼
Output
```

The original input is gone.

---

# With residuals

```text
Input
   │
   ├───────────────┐
   │               │
   ▼               │

   │               │
   ▼               │
Dropout            │
   │               │
   ▼               │
      Add ◄────────┘
       │
       ▼

```

Notice

The original input never disappears.

# Why normalize BEFORE the sublayer?

You might have seen diagrams like

```text

↓

Add

↓

LayerNorm
```

That is the **original Transformer paper (Post-LN)**.

Your implementation does

```text
LayerNorm

↓

Attention

↓

Add
```

This is called

```text
Pre-LN Transformer
```

Modern models like

- GPT
    
- LLaMA
    
- Mistral
    

use this version because it's much easier to train.

# Why add instead of replace?

Imagine the attention layer makes a mistake.

Without residual

```text
Original

↓

Wrong Attention

↓

Everything is ruined.
```

With residual

```text
Original

↓

Wrong Attention

↓

Original + Small Error
```

The original information is still present.

This makes optimization much easier.

# Why pass the sublayer as an argument?

This is one of the nicest parts of the implementation.

Instead of writing

```python

```

and

```python
FeedForwardResidual
```

the author wrote one reusable class.

```python

    x,
    self.self_attention

```

```python

x = Dropout(x)

```

Later

```python

    x,
    self.feed_forward
)
```

Internally

```python

x = FeedForward(x)

x = Dropout(x)

x = Original + x
```

The **only** thing that changes is the `sublayer`. Everything else—normalize, dropout, and add the skip connection—is identical.

# The complete flow inside one Transformer block

Putting it all together, a Pre-LN Transformer block looks like this:

```text
Input
  │
  ▼
LayerNorm
  │
  ▼
Multi-Head Attention
  │
  ▼
Dropout
  │
  ▼
Add Original Input (Residual)
  │
  ▼
Intermediate Output
  │
  ▼
LayerNorm
  │
  ▼
Feed Forward Network
  │
  ▼
Dropout
  │
  ▼
Add Intermediate Output (Residual)
  │
  ▼
Final Output
```

Notice that **the same `ResidualConnections` class is used twice**:

1. Once with the **Multi-Head Attention** sublayer.
    
2. Once with the **Feed Forward Network** sublayer.
    

The `sublayer` argument is simply a placeholder for "whatever computation this residual block should wrap." Once you see it this way, the implementation becomes a clean abstraction instead of two nearly identical pieces of code.

# Doubt

>Still a bit confused about the normalization, do we normalize the attention output, or the initial input, or do we add the input+difference and then normalize and when we add the attention output, does the attention output only give out the difference that we add to the original input ,how does that work

This is **the** question that usually makes transformers "click." The confusion comes from mixing up **what the attention layer computes** with **what the residual connection does**.

Let's separate them completely.

---

# First misconception

You asked:

> Does the attention output only give out the difference that we add to the original input?

**No.**

The attention layer has **no idea** it's going to be added back later.

It simply produces a **new representation** of every token.

For example,

Original embedding for "cat"

```text
[2, 5, 1]
```

Attention might output

```text
[8, -3, 4]
```

or

```text
[0.2, 1.1, -0.8]
```

or literally any vector.

The attention layer isn't trying to compute

```text
difference
```

It is simply computing

```text
new representation
```

The **residual connection** is what turns that into

```text
original + new representation
```

# Then why normalize at all?

Because attention works much better on stable inputs.

Imagine these embeddings

```text
Token1

[0.2,0.5,-0.1]
```

Token2

```text
[1000,-500,800]
```

The second token dominates everything.

LayerNorm makes them comparable before attention.

So LayerNorm is basically saying

> "Attention, here's a nicely scaled version of the sentence."

It doesn't permanently modify the sentence.

# Why not normalize AFTER addition?

Good question.

There are two transformer designs.

---

## Original Transformer (Post-LN)

```
Attention

↓

Add Residual

↓

LayerNorm
```

Flow:

```text
x

↓

Attention

↓

Attention Output

↓

x + Attention

↓

LayerNorm
```

---

## Modern Transformers (Pre-LN)

```
LayerNorm

↓

Attention

↓

Add Residual
```

Flow:

```text
x

↓

LayerNorm

↓

Attention

↓

Attention Output

↓

x + Attention Output
```

Your implementation is **Pre-LN**.

Modern models almost all use it because gradients flow better.

# Another question:

> If attention isn't computing a correction, why does adding it work?

Excellent question.

Think of it this way.

Suppose

```text
Original

"I love apples."
```

Attention discovers

```text
"love" should pay attention to "apples"
```

It updates the embedding of

```text
love
```

to include that information.

Suppose

Original

```text
love

=

[2,3,1]
```

Attention says

```text
Because of apples,

love should become

[5,7,2]
```

Residual gives

```text
[2,3,1]

+

[5,7,2]

=

[7,10,3]
```

The network doesn't interpret that as

```text
Original + Difference
```

It simply learns weights knowing this addition will happen.

During training, if the addition makes values too large, the model adjusts the learned weights (`W_q`, `W_k`, `W_v`, `W_o`) accordingly.

# The key intuition

The attention layer and the residual connection are **not designed independently**.

During training:

```
Input
   │
LayerNorm
   │
Attention
   │
Add Original
   │
Loss
```

The loss is backpropagated through **the entire pipeline**.

That means the attention layer gradually learns to produce outputs that are useful **when added to the original input**, because that's how it's always used during training.

So while the attention output is not explicitly "the difference," it often behaves somewhat like a refinement or update in practice, since the model has learned under the constraint that its output will always be combined with the original embedding.

This is why many people describe the residual branch as learning a "residual" or "correction." It's a useful intuition, but it's not something explicitly enforced by the architecture. The attention layer simply learns whatever output minimizes the training loss when used inside the residual connection.
