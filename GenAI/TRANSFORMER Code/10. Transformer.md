# Now look carefully

Your class has



Usually people write

Likewise

# So why write three separate methods?

Instead of

```python
forward()
```

that does everything?

This is actually very useful.

Training

```text

↓

Decode

↓

Project
```

Inference

needs

```text
Encode once

↓

Decode many times

↓

Project many times
```

Remember inference.

We said

```text

↓

stored output

↓

Decoder

↓

Le

↓

Decoder

↓

chat

↓

Decoder

↓

```

The encoder should **not** run again every decoding step.

By exposing

```python

```

we can reuse the encoder output.

This design makes greedy decoding and beam search much cleaner.

# Xavier Initialization

Now this line.

```python
for p in transformer.parameters():
```

Every weight inside

```text
Embeddings

Attention

FeedForward

Projection
```

is visited.

Notice

```python
if p.dim() > 1
```

Why?

Biases are

```text
(512)
```

One-dimensional.

Weight matrices are

```text
(512,512)
```

Two-dimensional.

Xavier initialization only applies to weight matrices.

---

Then

```python
nn.init.xavier_uniform_(p)
```

Instead of random numbers like

```text
1000

-800

400
```

we initialize with carefully chosen small values.

Why?

Because if weights start too large:

- activations can explode,
    
- gradients can explode or vanish,
    
- training becomes unstable.
    

Xavier initialization keeps the variance of activations roughly constant across layers, making optimization much easier.

# A few bugs to fix

Your code has a handful of small mistakes that are common when assembling everything:

1. The methods should be named `encode()` and `decode()`, not `encoder()` and `decoder()`, to avoid clashing with `self.encoder` and `self.decoder`.
    
2. There's a typo:
    

```python
self.src_emebed(src)
```

should be

```python
self.src_embed(src)
```

3. In `FeedForwardBlock` construction for the decoder, you have:
    

```python
FeedForwardBlock(d_model, h, d_ff, dropout)
```

Earlier, your constructor accepted `(d_model, d_ff, dropout)`, so the extra `h` doesn't belong unless you've changed the class definition.

4. The loop should be:
    

```python
for p in transformer.parameters():
```

not

```python
transformer.paramters()
```

The important realization is that this `Transformer` class isn't introducing a new algorithm. It's simply **orchestrating** the components you've already learned in exactly the order that data flows through the network. Once you see it as the "wiring diagram" rather than another complex model, it becomes much easier to reason about.
