## Translation: from scratch vs. pretrain-first

Both approaches exist, and it depends on data availability:

**Training directly on input-output pairs (from scratch)** — this is exactly what your `train.py` does. You take a randomly-initialized (Xavier-init) transformer and train it purely on English-French sentence pairs from `opus_books`. This works when you have a large enough parallel corpus, and it's how the original "Attention Is All You Need" paper trained its translation models — no pretraining step, just millions of sentence pairs, trained end-to-end. It's simpler, but the model has to learn _both_ "what language even is" _and_ "how to translate" from the same limited signal.

**Pretrain-then-finetune** — pretrain the model on large amounts of general unlabeled text first (learning grammar, world knowledge, how language works generally), then finetune on the smaller labeled translation pairs. Modern high-quality translation systems (and most large-scale NLP work today) do this, because general language understanding transfers — a model that already "knows" French grammar from pretraining needs far fewer parallel examples to learn the _mapping_ between English and French than one starting from zero. This is more relevant when parallel data is scarce (like low-resource language pairs) but general monolingual text is abundant.

For your English-French project specifically: `opus_books` is a reasonably large, clean corpus, so training from scratch (what your script does) is a legitimate and standard approach — this is the from-scratch route, no pretraining involved.

## Decoder-only models

This is the architecture your **Nepali nanoGPT project** actually uses (GPT-style), and it's structurally simpler than the encoder-decoder you've been studying — it's literally just the decoder half, with the cross-attention removed since there's no encoder output to attend to.

**Architecture, stripped down:**

```
tokens → InputEmbeddings → PositionalEmbedding
   → N x DecoderBlock(x)   [self-attention (causal) + FFN, NO cross-attention]
   → final LayerNorm
   → ProjectionLayer → next-token logits
```

Each `DecoderBlock` here only has **self-attention + feed-forward**, two residual connections instead of three — the cross-attention sublayer simply doesn't exist because there's no separate source sequence to attend to. Everything attends only to itself, causally masked.

**What it's pretrained on:** raw, unlabeled text — just a giant pile of documents (your ~22GB Nepali corpus, in your case). No input-output pairs, no translation labels, nothing curated. The "label" is generated automatically from the text itself: **next-token prediction**. Given any sequence of tokens, the training objective is simply "predict the token that comes next." That's the entire pretraining task — it's called _self-supervised_ learning because the supervision signal (the correct next token) comes for free from the raw text, no human labeling required.

Concretely, for the sentence "म भात खान्छु" tokenized as `[म, भात, खान्छु]`:

- input `[म]` → predict `भात`
- input `[म, भात]` → predict `खान्छु`
- input `[म, भात, खान्छु]` → predict `[EOS]`

All of these are extracted from **one single training sentence**, and because of causal masking, a decoder-only model actually computes _all_ these predictions in one forward pass, in parallel — the same "teacher forcing" idea from before, just applied to raw text instead of translation pairs. The "input-output pair" is just the sequence shifted by one position against itself: `input = tokens[:-1]`, `label = tokens[1:]`.

**Autoregressive generation, for a decoder-only model specifically:**

Since there's no `encode` step at all (no separate source sequence), generation is even more directly "keep feeding yourself back in":

```
prompt tokens → decoder(prompt) → project → pick next token
→ append that token to the sequence
→ decoder(prompt + new_token) → project → pick next token
→ append, repeat...
```

Compare this to your encoder-decoder's `greedy_decode`: there, `encoder_output` is computed _once_ and reused, while only `decoder_input` grows each step. In a decoder-only model, there's no separate encoder output to cache in that sense — the entire growing sequence itself is both the "source" and the thing being extended, re-run through the same self-attention stack every step. (In practice, well-optimized decoder-only inference uses **KV caching** so it doesn't recompute attention over the whole growing sequence from scratch each time — mentioned last message — this is especially important for decoder-only models since generation is the primary use case, not just a side feature like in translation.)

This is also why decoder-only models are the natural fit for your nanoGPT project: you don't have (and don't need) parallel translation-style pairs — you just need raw Nepali text, and the model teaches itself by trying to predict what comes next, over and over, across your entire corpus.
