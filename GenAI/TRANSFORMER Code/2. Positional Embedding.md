```python
class PositionalEmbedding(nn.Module):
    def __init__(self, d_model: int, seq_len: int, dropout: float):
        '''
        d_model: additional matrix that has the same dense vector dimensions
        seq_len: the sentence size
        dropout: kills neurons termporarily to avoid overfitting
        pe: matrix of size (seq_len x d_model)
        '''
        
        super().__init__()
        self.d_model = d_model
        self.seq_len = seq_len
        self.dropout = nn.Dropout(dropout)
    
        pe = torch.zeros(seq_len, d_model)

        # create a vector of size(seq_len) to indicate position of word in sentence. Range(0, n-1)
        position = torch.arange(0, seq_len, dtype=torch.float).unsqueeze(1) # (seq_len, 1)

        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))

        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        
        pe = pe.unsqueeze(0) # (1, seq_len, d_model) , batch dimension, as in for multiple sentences

        self.register_buffer('pe', pe) # to save tensor values when mode is being saved

    
    def forward(self, x):
        x = x + (self.pe[:, :x.shape[1], :]).requires_grad_(False) # to void this from being learned in backprop
        return self.dropout(x)



```

This is one of the most important pieces of the original Transformer. I'll explain **what every line is doing**, but more importantly, **why** it exists.

First, let's remember where this fits in the pipeline.

```text
Sentence
    │
Tokenizer
    │
Token IDs
    │
Embedding Layer
    │
(batch_size, seq_len, d_model)
    │
+ Positional Encoding  ← This class
    │
Transformer Encoder
```

The embedding layer knows **what** each word is, but it has no idea **where** it appears in the sentence.

For example,

```text
Dog bites man

and

Man bites dog
```

contain exactly the same words.

Without positional information, the embeddings would just be

```text
dog
bites
man
```

or

```text
man
bites
dog
```

and the transformer wouldn't know which came first.

# Why sine and cosine?

Because they have useful mathematical properties.

Nearby positions produce similar vectors.

```
Position 5

↓

vector A

Position 6

↓

vector B

A and B are similar.
```

But

```
Position 5

Position 95
```

produce very different vectors.

This helps attention learn distances.

### Buffers

These are tensors that

- move to GPU with the model
    
- get saved with the model
    
- **are NOT trained**
    

The positional encoding is fixed, so it belongs here.

## Why `.requires_grad_(False)`?

Your code uses:

```python
.requires_grad(False)
```

The usual PyTorch style is:

```python
.requires_grad_(False)
```

or simply relying on the fact that `register_buffer` already creates a non-trainable tensor.

The intent is the same: **do not compute gradients for the positional encoding**, because in the original Transformer these values are fixed mathematical functions, not learned parameters.

---

```python

```

returns the position-aware embeddings after applying dropout.

2. This line should assign the result back:

# Doubt
> self.pe[:, :x.shape[1], :], this line just confuses me, just simplify this

Absolutely. Let's ignore transformers for a minute and just learn **tensor slicing**.

Suppose `self.pe` has shape

```text
(1, 100, 512)
```

This means

```text
Batch: 1
Sentence positions: 100
Embedding size: 512
```

You can picture it like this:

```text
self.pe

Batch 0

Position 0  → [512 numbers]
Position 1  → [512 numbers]
Position 2  → [512 numbers]
...
Position 99 → [512 numbers]
```

---

Now suppose your input sentence is only **8 words** long.

Then

```python
x.shape
```

is

```text
(32, 8, 512)
```

where

- 32 = batch size
    
- 8 = sentence length
    
- 512 = embedding dimension
    

So

```python
x.shape[1]
```

means

```text
8
```

because index `1` is the **sequence length**.

---

Now look at the slicing:

```python
self.pe[:, :x.shape[1], :]
```

Replace `x.shape[1]` with `8`.

It becomes

```python
self.pe[:, :8, :]
```

Now read it one dimension at a time.

### First `:`

```python
self.pe[:, ...]
```

means

> Take **all batches**.

There's only one anyway.

---

### Second `:8`

```python
self.pe[:, :8, ...]
```

means

> Take **positions 0 through 7**.

So instead of all 100 positions, we keep only the first 8.

---

### Third `:`

```python
self.pe[:, :8, :]
```

means

> Take **all 512 embedding values** for each position.

---

So the result has shape

```text
(1, 8, 512)
```

which matches your sentence length.

---

### Why not just use the whole matrix?

Suppose you precomputed positional encodings for

```text
100 positions
```

but today's sentence is only

```text
8 words
```

You only need

```text
Position 0
Position 1
...
Position 7
```

There's no point adding encodings for positions 8–99 because those words don't exist in this sentence.

---

So this line:

```python
self.pe[:, :x.shape[1], :]
```

is simply saying:

> **"Give me the positional encodings for exactly as many positions as this sentence has."**

If the sentence has:

- 8 words → get positions `0–7`
    
- 20 words → get positions `0–19`
    
- 75 words → get positions `0–74`
    

Nothing more complicated than that. It's just slicing the precomputed positional encoding matrix to the current sentence length.
