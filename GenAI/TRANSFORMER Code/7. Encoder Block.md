```python
class EncoderBlock(nn.Module):
    def __init__(self, self_attention_block : MultiHeadAttention, feed_forward_block: FeedForwardBlock, dropout: float):
        super().__init__()
        self.self_attention_block = self_attention_block
        self.feed_forward_block = feed_forward_block
        self.residual_connections = nn.ModuleList([ResidualConnections(dropout) for _ in range(2)])
    
    def forward(self, x, src_mask):
        x = self.residual_connections[0](x, lambda x: self.self_attention_block(x, x, x, src_mask))
        x = self.residual_connections[1](x, self.feed_forward_block)
        return x
    

class Encoder(nn.Module):
    def __init__(self, layers: nn.ModuleList):
        super().__init__()
        self.layers = layers
        self.norm = LayerNormalization()
    
    def forward(self, x, mask):
        for layer in self.layers:
            x = layer(x, mask)
        
        return self.norm(x)
```

These are excellent questions. In fact, these three things—

1. **Why is self-attention wrapped in a `lambda` but feed-forward isn't?**
    
2. **Why does self-attention need all those arguments while feed-forward doesn't?**
    
3. **Why is there one more `LayerNorm` after all encoder blocks?**
    

—are related. Let's go one at a time.

---

# First, what does one Encoder Block contain?

One encoder block is simply

```text
Input
   │
   ▼
Residual(
    Self-Attention
)
   │
   ▼
Residual(
    Feed Forward
)
   │
   ▼
Output
```

So the code

```python
x = self.residual_connections[0](...)
x = self.residual_connections[1](...)
```

is literally implementing those two boxes.

---

# Question 1

## Why does self-attention receive four arguments?

Look at its forward function.

```python
def forward(self, q, k, v, mask):
```

It expects

```text
Query

Key

Value

Mask
```

For **encoder self-attention**, they are all identical.

So we call

```python
self.self_attention_block(x, x, x, src_mask)
```

Meaning

```text
Q = x

K = x

V = x
```

This is why it's called **self-attention**.

The sentence attends to itself.

---

# Why doesn't FeedForward need that?

Look at its forward.

```python
def forward(self, x):
```

That's all it needs.

Remember the FFN never compares words.

It only transforms each token independently.

So

```python
feed_forward(x)
```

is enough.

There are no

```text
Q

K

V
```

inside the FFN.

---

# Then why not write

```python
self.residual_connections[0](
    x,
    self.self_attention_block
)
```

like we did for FeedForward?

This is where `lambda` comes in.

---

# What does ResidualConnection expect?

Remember its forward.

```python
def forward(self, x, sublayer):
```

Inside it, we do

```python
sublayer(self.norm(x))
```

Notice carefully.

ResidualConnection only knows how to call

```python
sublayer(
    some_input
)
```

That means

`sublayer` must be a function that accepts **one argument**.

---

## FeedForward already matches that.

Its forward is

```python
forward(x)
```

Perfect.

ResidualConnection can simply call

```python
feed_forward(x)
```

No problem.

---

## SelfAttention does NOT match.

Its forward is

```python
forward(q,k,v,mask)
```

Four arguments.

ResidualConnection is trying to call

```python
self_attention(
    normalized_x
)
```

That would produce

```text
TypeError

missing 3 required arguments
```

---

# So lambda creates a new one-argument function

This line

```python
lambda x:
    self.self_attention_block(
        x,
        x,
        x,
        src_mask
    )
```

creates a tiny function.

Imagine writing

```python
def my_attention(y):
    return self.self_attention_block(
        y,
        y,
        y,
        src_mask
    )
```

Now

```python
my_attention
```

accepts exactly one argument.

ResidualConnection is happy.

So

```python
sublayer(self.norm(x))
```

becomes

```python
my_attention(
    self.norm(x)
)
```

which expands to

```python
self.self_attention_block(
    self.norm(x),
    self.norm(x),
    self.norm(x),
    src_mask
)
```

This is exactly what we wanted.

---

# So lambda is just a wrapper.

Think

```text
ResidualConnection

↓

"I only know how to call

function(input)"
```

SelfAttention says

```text
"I need four inputs!"
```

Lambda says

```text
"I'll handle the extra arguments.

You only pass me x."
```

That's all.

---

# Why don't we use lambda for FeedForward?

Because

FeedForward already looks like

```python
feed_forward(x)
```

It already satisfies

```text
one input

↓

one output
```

No wrapper needed.

# Let's visualize the first residual.

Code

```python
self.residual_connections[0](
    x,
    lambda x:
        self.self_attention_block(
            x,x,x,src_mask
        )
)
```

Internally becomes

```python
normalized = LayerNorm(x)

attention = self_attention(
    normalized,
    normalized,
    normalized,
    src_mask
)

attention = Dropout(attention)

output = x + attention
```

Exactly like the Transformer paper.

---

# Second residual

This

```python
self.residual_connections[1](
    x,
    self.feed_forward_block
)
```

internally becomes

```python
normalized = LayerNorm(x)

ff = feed_forward(normalized)

ff = Dropout(ff)

output = x + ff
```

Exactly the same pipeline.

Only the sublayer changes.

# Then comes the confusing part

```python

```

Why another LayerNorm?

Remember

Each EncoderBlock already contains

```text
LayerNorm

↓

Attention

↓

Residual

↓

LayerNorm

↓

FeedForward

↓

Residual
```

So why another one?

---

## Historical reason

The original Transformer ended the encoder with one more normalization.

Modern implementations usually keep it.

Think of it as

```text
Clean up the final representation
```

before sending it to the decoder.

---

Suppose after six layers

you have

```text
Large values

Small values

Different variances
```

Final LayerNorm makes them consistent.

---

Visual

```text
Embedding

↓

Block1

↓

Block2

↓

Block3

↓

Block4

↓

Block5

↓

Block6

↓

Final LayerNorm

↓

Encoder Output
```

---

# Why isn't the last normalization inside Block6?

Because Block6 normalizes **before** its attention and feed-forward sublayers (Pre-LN). After the final residual addition in Block6, there is **no subsequent sublayer** that would normalize the output. The encoder itself adds one last normalization so that the representation passed to the decoder is well-conditioned.

Think of it like a factory:

```text
Machine 1

↓

Machine 2

↓

Machine 3

↓

Quality Inspection
```

Each machine checks its own inputs, but the factory still performs one final inspection before shipping the product.

# Putting everything together

Here's the complete flow through an encoder with two blocks (for simplicity):

```text
Input Embeddings
        │
        ▼
Encoder Block 1
    │
    ├── LayerNorm
    ├── Self-Attention
    ├── Dropout
    ├── Add Residual
    ├── LayerNorm
    ├── Feed Forward
    ├── Dropout
    └── Add Residual
        │
        ▼
Encoder Block 2
    │
    ├── LayerNorm
    ├── Self-Attention
    ├── Dropout
    ├── Add Residual
    ├── LayerNorm
    ├── Feed Forward
    ├── Dropout
    └── Add Residual
        │
        ▼
Final LayerNorm
        │
        ▼
Encoder Output
```

One final subtle point: that last `LayerNorm` is only needed because this is a **Pre-LN** architecture. In a **Post-LN** Transformer (the original paper), each block ends with a normalization _after_ the residual addition, so the output of the last block is already normalized. In a Pre-LN Transformer, each block **starts** with normalization, leaving the very final output unnormalized unless the encoder applies one last `LayerNorm`. That's why you see `self.norm(x)` at the end of the `Encoder` class.
