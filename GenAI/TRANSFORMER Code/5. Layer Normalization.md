```python
class LayerNormalization(nn.Module):
    def __init__(self, eps: float = 10**-6) -> None:
        super().__init__()
        self.eps = eps
        self.alpha = nn.Parameter(torch.ones(1)) # multiplicative and nn.parameter makes it learnables
        self.bias = nn.Parameter(torch.ones(1)) # additive term
    
    def forward(self, x):
        mean = x.mean(dim=-1, keepdims = True)
        std = x.mean(dim=-1, keepdims = True)
        return self.alpha * (x - mean) / (std + self.eps) + self.bias

```

This is another fundamental building block of transformers. Before we look at the code, let's answer **why Layer Normalization exists**.

Imagine one token embedding coming out of a layer.

```text

```

Some values are very large, some are negative.

After many transformer layers, these values can become even larger or smaller, making training unstable.

**Layer Normalization** rescales them so they have a consistent distribution before passing them to the next layer.

# When is `forward()` called?

This is something many people miss when learning PyTorch.

You **never** call `forward()` directly.

Instead you do

```python
layer_norm = LayerNormalization()
```

Then

```python
y = layer_norm(x)
```

Notice

You didn't write

```python
layer_norm.forward(x)
```

PyTorch automatically calls

```python
forward(x)
```

behind the scenes.

Internally it's roughly doing

```python
def __call__(self, x):
    return self.forward(x)
```

So

```python
layer_norm(x)
```

automatically invokes

```python
forward(x)
```

# When is LayerNorm used in a Transformer?

A transformer block looks roughly like this:

```text
Input
   │
   ▼
Multi-Head Attention
   │
   ▼
Add Residual
   │
   ▼
LayerNorm   ← your class
   │
   ▼
Feed Forward Network
   │
   ▼
Add Residual
   │
   ▼
LayerNorm   ← again
   │
Output
```

So **every time** data reaches a LayerNorm layer during the forward pass of the transformer, PyTorch executes this `forward()` method automatically.

# Doubt
> Why do we keep the keepdim as True

The biggest advantage is that it makes **broadcasting work automatically**.

Let's use a much smaller example.

Suppose one token embedding is

```python
x = torch.tensor([[2., 4., 6.]])
```

Shape:

```text
(1, 3)
```

---

### Without `keepdim=True`

```python
mean = x.mean(dim=-1)
```

Result:

```text
tensor([4.])

Shape:
(1,)
```

The dimension you averaged over disappears.

---

### With `keepdim=True`

```python
mean = x.mean(dim=-1, keepdim=True)
```

Result:

```text
tensor([[4.]])

Shape:
(1,1)
```

The dimension stays, but its size becomes `1`.

---

## Why is this useful?

Suppose you want to normalize:

```python
x - mean
```

### `x`

```text
[[2,4,6]]

Shape:
(1,3)
```

### `mean`

With `keepdim=True`

```text
[[4]]

Shape:
(1,1)
```

PyTorch automatically broadcasts it:

```text
[[2,4,6]]
-
[[4,4,4]]
```

Result:

```text
[[-2,0,2]]
```

Everything lines up naturally.

---

## In the transformer

Suppose

```python
x.shape = (32, 20, 512)
```

meaning

- 32 sentences
    
- 20 tokens each
    
- 512-dimensional embeddings
    

Now compute

```python
mean = x.mean(dim=-1, keepdim=True)
```

Shape becomes

```text
(32,20,1)
```

Notice what happened.

For **every token**, instead of storing 512 means (which wouldn't make sense), we store **one mean**:

```text
Sentence 1

Token 1 → mean = 0.42

Token 2 → mean = 0.37

...

Sentence 32

Token 20 → mean = 0.51
```

When you do

```python
x - mean
```

PyTorch sees

```text
x      : (32,20,512)

mean   : (32,20,1)
```

and automatically stretches that last dimension:

```text
(32,20,1)

↓

(32,20,512)
```

so every one of the 512 values in a token has the same mean subtracted.

---

### Could you do it without `keepdim=True`?

Yes.

You could write:

```python
mean = x.mean(dim=-1)
mean = mean.unsqueeze(-1)
```

This produces exactly the same shape `(32,20,1)`.

So `keepdim=True` is really just a convenience—it saves you from writing an extra `unsqueeze()` and keeps the tensor shapes compatible for broadcasting right away.
