## Part 1: CNN fundamentals, simplified

### Convolution — the core operation

A convolutional layer slides a small filter (called a **kernel**) across the image, patch by patch. At each spot, it multiplies the pixels under it by some learned numbers, adds those up, and that sum becomes one output value. Think of it like a small stencil being dragged across the image, checking "how much does this patch look like the pattern I'm looking for?"

The big idea: **the same stencil is reused everywhere** in the image. It doesn't get a fresh, separate set of weights for each position — one kernel slides across the whole image using the same weights the whole time. This is why CNNs are good at spatial stuff — a kernel that's learned to spot "an edge" will spot edges anywhere in the picture, not just in one corner.

Each kernel produces one **feature map** — basically a new, smaller grid showing "where did this pattern show up." A layer usually runs many kernels side by side, each hunting for a different pattern. So a layer might take in a 224×224×3 image (3 = red, green, blue) and output 224×224×64 — 64 different feature maps, each one tracking a different kind of pattern.

### Key terms you'll keep seeing

- **Channels (depth):** How many feature maps are stacked at some point in the network. The input image starts with 3 (R, G, B). Deeper in the network, you might have 512 or 1024 — each one a different thing the network learned to detect.
- **Stride:** How big a jump the kernel takes each step. Stride 1 = move one pixel at a time (output stays close to the same size). Stride 2 = skip every other pixel (output shrinks to about half).
- **Padding:** Adding a thin border of zeros around the image so the kernel can still center properly on edge pixels. With padding, output size can stay the same as input size; without it, the output shrinks a bit each time.
- **Pooling (e.g. max pooling):** A separate, simple shrinking step — look at a small window (say 2×2) and just keep the biggest number in it, throw the rest away. This is just a fast way to shrink the image size as you go deeper — no learning involved, just picking the strongest signal.
- **Receptive field:** How much of the _original image_ a single output number is "aware of," indirectly, after passing through several layers. Early on, each output only "sees" a tiny patch (just edges, textures). After many layers, each output has indirectly absorbed a huge chunk of the image — enough to represent something like "this looks like a dog's face," not just "this is a line."

### Why depth increases while spatial size decreases

This pattern shows up in basically every CNN, including YOLO's: the deeper you go, the image gets **smaller** but **deeper** — fewer pixels, but way more channels.

Early layers: big image (224×224), few channels (64) — looking at lots of raw detail, but only simple patterns. Later layers: tiny image (7×7), tons of channels (1024) — barely any spatial detail left, but lots of higher-level "concepts" detected at each spot.

This trade-off is intentional. By the time you're deep in the network, you don't need to know exactly which pixel something is at — you need to know _what's_ there (a wheel? fur? sky?). That kind of rich information needs many channels, not many pixels.

### 1×1 convolutions (a trick YOLO borrows from GoogLeNet/Inception)

A 1×1 kernel doesn't look at neighboring pixels at all — it only looks at one position, and just mixes the channels there. So if you have 512 channels coming in, and you apply a 1×1 conv with 128 output channels, you're basically squashing those 512 numbers down into 128, at every position — no spatial mixing, purely channel mixing.

**Why bother?** It's a cheap way to shrink channel count _before_ doing an expensive 3×3 conv. A 3×3 conv across 512 channels is heavy — lots of weights to learn. So instead, you first cheaply squeeze 512 → 128 channels with a 1×1 conv, then run the 3×3 conv on just those 128 channels. Much less computation for roughly the same benefit. You'll see this "squeeze then expand" pattern repeat constantly through YOLOv1's backbone — it's a direct borrow from Inception/GoogLeNet.

### Activation functions — why they're needed at all

If you stacked conv layers with nothing in between, no matter how many layers you piled on, the whole thing would mathematically collapse into one simple operation — it could only ever learn straight-line relationships, nothing complex. An activation function (applied after every conv layer) breaks that — it's what lets the network learn bendy, complicated patterns instead of just straight lines.

YOLOv1 uses **Leaky ReLU**: if a value is positive, keep it as-is; if it's negative, shrink it down a lot (multiply by 0.1) instead of zeroing it out completely. (Plain ReLU just kills negatives entirely — leaky ReLU keeps a tiny trickle alive, which can help training stay stable.)

## Part 2: How this assembles into YOLOv1's actual backbone

Now the structure makes sense as a sequence of decisions rather than a magic number "24 layers":

|Stage|What happens|Spatial size|Channels|
|---|---|---|---|
|Input|raw image|448×448|3|
|Conv block 1|7×7 conv, stride 2 + maxpool|224×224 → 112×112|64|
|Conv blocks 2-4|mix of 1×1 (squeeze) and 3×3 convs + pooling|shrinks progressively|192 → 256 → 512|
|Conv blocks 5-6|more 1×1/3×3 stacking, final pooling|down to 7×7|up to 1024|
|FC layers|flatten, fully connected|7×7×1024 → flat vector|→ reshaped to 7×7×30|

So the whole backbone is just: repeatedly apply (conv → activation → sometimes pool), letting spatial size shrink from 448 down to 7, while channel depth grows from 3 up to 1024 — exactly the universal CNN trade-off above. The 1×1/3×3 alternating pattern is the Inception-style squeeze trick, used purely to keep computation manageable at this depth.

**Where YOLO-specific design kicks in:** notice the spatial size lands _exactly_ at 7×7 by the final conv layer — that's not a coincidence, the architecture's strides/poolings are deliberately tuned so the last feature map's spatial grid **is** the S×S grid (S=7) we've been discussing this whole conversation. Each of those 49 spatial positions in the final feature map, after the FC layers reshape things, becomes one of our 49 "responsible cells."

> **Later-version flag:** Those final 2 fully-connected layers are exactly the weak point we flagged before — flattening a 7×7×1024 map into one giant FC layer destroys the natural property that "feature map position ≈ image position" (a property the conv layers maintained perfectly up to that point). YOLOv2 removes the FC layers entirely and instead just adds a final 1×1 conv that outputs 7×7×(B×5+C) directly from the conv feature map — fully convolutional end-to-end, preserving spatial correspondence and letting the network handle any input resolution.
