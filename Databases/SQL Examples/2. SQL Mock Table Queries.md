## Database Schema

```sql
users(user_id PK, name, email, city, signup_date)

restaurants(restaurant_id PK, name, city, cuisine_type, rating)

menu_items(item_id PK, restaurant_id FK -> restaurants, item_name, price, is_veg)

delivery_agents(agent_id PK, name, city, joining_date)

orders(order_id PK, user_id FK -> users, restaurant_id FK -> restaurants, agent_id FK -> delivery_agents,
       order_date, status, delivery_time_minutes)  -- status: 'placed','delivered','cancelled'

order_items(order_item_id PK, order_id FK -> orders, item_id FK -> menu_items, quantity, unit_price)

ratings(rating_id PK, order_id FK -> orders, user_id FK -> users, restaurant_id FK -> restaurants,
        food_rating, delivery_rating, rating_date)
```

##  **1. Top 3 restaurants by total revenue **

_Pattern:_ Simple aggregation with join, grain = one row per restaurant. _Approach:_ Revenue lives in `order_items` (quantity × unit_price), but I need it tied to `restaurant_id`, so join order_items → orders → restaurants (or order_items → menu_items, since menu_items already carries restaurant_id — fewer joins that way). Aggregate, sort, limit.

```sql
SELECT r.restaurant_id, r.name, SUM(oi.quantity * oi.unit_price) AS total_revenue
FROM restaurants r
JOIN menu_items mi ON mi.restaurant_id = r.restaurant_id
JOIN order_items oi ON oi.item_id = mi.item_id
GROUP BY r.restaurant_id, r.name
ORDER BY total_revenue DESC
LIMIT 3;
```

## **2. Best-rated restaurant per cuisine type **

_Pattern:_ "best per group" → window function, not plain GROUP BY. _Approach:_ First aggregate avg food_rating per restaurant (join restaurants → ratings, group by restaurant), then rank within `cuisine_type` using `RANK()`, filter `rnk = 1`.

```sql
WITH restaurant_avg AS (
  SELECT r.restaurant_id, r.name, r.cuisine_type, AVG(rt.food_rating) AS avg_rating
  FROM restaurants r
  JOIN ratings rt ON rt.restaurant_id = r.restaurant_id
  GROUP BY r.restaurant_id, r.name, r.cuisine_type
),
ranked AS (
  SELECT *, RANK() OVER (PARTITION BY cuisine_type ORDER BY avg_rating DESC) AS rnk
  FROM restaurant_avg
)
SELECT cuisine_type, restaurant_id, name, avg_rating
FROM ranked
WHERE rnk = 1;
```

## **3. Agents who delivered every month since joining **

_Pattern:_ "every month, no gaps" → COUNT(DISTINCT month) = expected number of months. _Approach:_ Trickier than the earlier version because "every month since joining" is a _variable_ target, not a fixed 12 — I need to calculate the expected month count per agent (months between joining_date and current date), then compare it to the distinct months they actually delivered in.
[[Horrible Date SQL Query]]
```sql
WITH agent_months_active AS (
  SELECT agent_id,
         (EXTRACT(YEAR FROM AGE(CURRENT_DATE, joining_date)) * 12
          + EXTRACT(MONTH FROM AGE(CURRENT_DATE, joining_date)) + 1) AS expected_months
  FROM delivery_agents
),
agent_months_delivered AS (
  SELECT agent_id, COUNT(DISTINCT DATE_TRUNC('month', order_date)) AS actual_months
  FROM orders
  WHERE status = 'delivered'
  GROUP BY agent_id
)
SELECT a.agent_id
FROM agent_months_active a
JOIN agent_months_delivered d ON d.agent_id = a.agent_id
WHERE a.expected_months = d.actual_months;
```

_Note:_ this is Postgres-flavored (`AGE`, `DATE_TRUNC`); the date-math function names change across dialects, but the logic — expected count vs. actual distinct count — stays the same.

## **4. Restaurants never rated **

_Pattern:_ "never" → anti-join. _Approach:_ `NOT EXISTS` against `ratings` for each restaurant.

```sql
SELECT r.restaurant_id, r.name
FROM restaurants r
WHERE NOT EXISTS (
  SELECT 1 FROM ratings rt WHERE rt.restaurant_id = r.restaurant_id
);
```

## **5. Running total spend per user **

_Pattern:_ "running/cumulative" → window aggregate with ORDER BY inside OVER(). _Approach:_ Get order-level totals first (sum of order_items per order), then apply a cumulative `SUM()` partitioned by user, ordered by date.

```sql
WITH order_totals AS (
  SELECT o.order_id, o.user_id, o.order_date,
         SUM(oi.quantity * oi.unit_price) AS order_value
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.order_id
  GROUP BY o.order_id, o.user_id, o.order_date
)
SELECT user_id, order_id, order_date, order_value,
       SUM(order_value) OVER (PARTITION BY user_id ORDER BY order_date
                               ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM order_totals
ORDER BY user_id, order_date;
```

## **6. Second-fastest avg delivery time restaurant per city, no LIMIT/OFFSET **

_Pattern:_ "Nth per group" → DENSE_RANK partitioned by group. _Approach:_ "Fastest" = lowest `delivery_time_minutes`, so aggregate avg delivery time per restaurant, rank ascending within city, filter rank = 2.

```sql
WITH restaurant_speed AS (
  SELECT r.restaurant_id, r.name, r.city, AVG(o.delivery_time_minutes) AS avg_delivery_time
  FROM restaurants r
  JOIN orders o ON o.restaurant_id = r.restaurant_id
  WHERE o.status = 'delivered'
  GROUP BY r.restaurant_id, r.name, r.city
),
ranked AS (
  SELECT *, DENSE_RANK() OVER (PARTITION BY city ORDER BY avg_delivery_time ASC) AS rnk
  FROM restaurant_speed
)
SELECT city, restaurant_id, name, avg_delivery_time
FROM ranked
WHERE rnk = 2;
```

## **7. Users whose avg order value > 2× platform-wide average **

_Pattern:_ multi-level aggregation (compare a group's aggregate to a grand aggregate) → CTE chain, filter with a scalar subquery. _Approach:_ Same shape as the e-commerce version, just with a `× 2` twist in the WHERE.

```sql
WITH order_totals AS (
  SELECT o.order_id, o.user_id, SUM(oi.quantity * oi.unit_price) AS order_value
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.order_id
  GROUP BY o.order_id, o.user_id
),
user_avg AS (
  SELECT user_id, AVG(order_value) AS avg_order_value
  FROM order_totals
  GROUP BY user_id
)
SELECT user_id, avg_order_value
FROM user_avg
WHERE avg_order_value > 2 * (SELECT AVG(order_value) FROM order_totals);
```

## **8. Month-over-month % change in delivered order count **

_Pattern:_ period-over-period comparison → LAG(). _Approach:_ Collapse delivered orders to a monthly count, then `LAG()` to pull the prior month's count into the same row, guard the divisor with `NULLIF`.

`NULLIF(value1, value2) compares 2 values, if both are same returns NULL, used to avoid div by 0 error. If values dont match the first value is returned`
```sql
WITH monthly_delivered AS (
  SELECT DATE_TRUNC('month', order_date) AS month, COUNT(*) AS delivered_orders
  FROM orders
  WHERE status = 'delivered'
  GROUP BY DATE_TRUNC('month', order_date)
)
SELECT month, delivered_orders,
       LAG(delivered_orders) OVER (ORDER BY month) AS prev_month,
       ROUND(100.0 * (delivered_orders - LAG(delivered_orders) OVER (ORDER BY month))
             / NULLIF(LAG(delivered_orders) OVER (ORDER BY month), 0), 2) AS pct_change
FROM monthly_delivered
ORDER BY month;
```

## **9. Restaurants with avg food_rating < 3 but > 10 ratings **

_Pattern:_ condition on aggregated values → HAVING, single group-by pass with compound condition. _Approach:_ No CTE needed — one aggregation, two conditions in HAVING.

```sql
SELECT r.restaurant_id, r.name, AVG(rt.food_rating) AS avg_food_rating, COUNT(*) AS rating_count
FROM restaurants r
JOIN ratings rt ON rt.restaurant_id = r.restaurant_id
GROUP BY r.restaurant_id, r.name
HAVING AVG(rt.food_rating) < 3 AND COUNT(*) > 10;
```

`or`

```sql
with average_ratings as(
    select r.restaurant_id, r.name, avg(rt.food_rating) as average_food_rating, count(*) as ratings_count
    from restaurants r
    join ratings rt on rt.restaurant_id = r.restaurant_id
    group by r.restaurant_id, r.name
)
select *
from average_ratings
where average_food_rating < 3 and ratings_count > 10
order by average_food_rating desc;
```

## **10. Frequently ordered-together menu item pairs (same restaurant only) **

_Pattern:_ relationship between rows in the same table → self-join with inequality to dedupe. _Approach:_ Same mechanics as the products example — self-join `order_items` on `order_id`, `a.item_id < b.item_id` to kill self-pairs/mirrors. The "same restaurant only" constraint is already naturally satisfied since items in one order come from one restaurant, but being explicit via a join to `menu_items` makes intent clear and guards against any multi-restaurant order edge case in your data model.

```sql
SELECT a.item_id AS item_a, b.item_id AS item_b, COUNT(*) AS times_together
FROM order_items a
JOIN order_items b ON a.order_id = b.order_id AND a.item_id < b.item_id
JOIN menu_items ma ON ma.item_id = a.item_id
JOIN menu_items mb ON mb.item_id = b.item_id AND mb.restaurant_id = ma.restaurant_id
GROUP BY a.item_id, b.item_id
ORDER BY times_together DESC;
```

`or`

```sql
select oi.order_item_id as product_a, oii.order_item_id as product_b, count(*) as times_brought_together
from order_items oi
join order_items oii on oii.order_item_id = oi.order_item_id
where oi.order_id > oii.order_id
group by oi.order_item_id, oii.order_item_id
order by times_brought_together desc;
```
