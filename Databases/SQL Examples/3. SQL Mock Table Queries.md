Let's go with a **library management system** — different relationship shapes (many-to-many via loans, self-referencing authors/members hierarchy potential) to stretch different patterns.

## Database Schema

```sql
members(member_id PK, name, email, city, membership_date)

authors(author_id PK, name, country)

books(book_id PK, title, author_id FK -> authors, genre, published_year, total_copies)

loans(loan_id PK, member_id FK -> members, book_id FK -> books,
      loan_date, due_date, return_date)  -- return_date NULL if not yet returned

fines(fine_id PK, loan_id FK -> loans, amount, paid_status)  -- paid_status: 'paid','unpaid'

reviews(review_id PK, book_id FK -> books, member_id FK -> members, rating, review_date)

staff(staff_id PK, name, role, branch_city)
```

Relationships: one author → many books; one member → many loans; one book → many loans (over time) & many reviews; one loan → at most one fine (if returned late or lost).

## **1. Top 3 members by total fines paid**

_Pattern:_ Simple aggregation with join, grain = one row per member.  
_Approach:_ Fines live in `fines`, tied to `loans`, tied to `members`. Filter to only `paid_status = 'paid'` since we want fines _paid_, not just incurred. Join up, group by member, sum, sort, limit.

```sql
SELECT m.member_id, m.name, SUM(f.amount) AS total_fines_paid
FROM members m
JOIN loans l ON l.member_id = m.member_id
JOIN fines f ON f.loan_id = l.loan_id
WHERE f.paid_status = 'paid'
GROUP BY m.member_id, m.name
ORDER BY total_fines_paid DESC
LIMIT 3;
```

## **2. Most-loaned book per genre**

_Pattern:_ "most per group" → window function, not plain GROUP BY.  
_Approach:_ Aggregate loan count per book (join books → loans, group by book), then rank within `genre` using `RANK()`, filter `rnk = 1`.

```sql
WITH book_loan_counts AS (
  SELECT b.book_id, b.title, b.genre, COUNT(*) AS loan_count
  FROM books b
  JOIN loans l ON l.book_id = b.book_id
  GROUP BY b.book_id, b.title, b.genre
),
ranked AS (
  SELECT *, RANK() OVER (PARTITION BY genre ORDER BY loan_count DESC) AS rnk
  FROM book_loan_counts
)
SELECT genre, book_id, title, loan_count
FROM ranked
WHERE rnk = 1;
```

## **3. Members who borrowed from every genre**

_Pattern:_ "every X" → COUNT(DISTINCT unit) = total possible units. The twist here: the target isn't a fixed number like 12 months — it's however many genres exist in the library, so that has to be computed, not hardcoded.  
_Approach:_ Get the total distinct genre count first (scalar subquery), then for each member count their distinct genres borrowed from, and compare.

```sql
SELECT m.member_id, m.name
FROM members m
JOIN loans l ON l.member_id = m.member_id
JOIN books b ON b.book_id = l.book_id
GROUP BY m.member_id, m.name
HAVING COUNT(DISTINCT b.genre) = (SELECT COUNT(DISTINCT genre) FROM books);
```

## **4. Books never loaned**

_Pattern:_ "never" → anti-join.  
_Approach:_ `NOT EXISTS` against `loans` for each book.

```sql
SELECT b.book_id, b.title
FROM books b
WHERE NOT EXISTS (
  SELECT 1 FROM loans l WHERE l.book_id = b.book_id
);
```

## **5. Running count of books borrowed per member**

_Pattern:_ "running/cumulative" → window aggregate with ORDER BY inside OVER(). Note this is a _count_, not a sum — same mechanism, different aggregate function.  
_Approach:_ No pre-aggregation needed since each loan row already = one borrow event. Just apply `COUNT(*)` as a window function ordered by loan_date.

```sql
SELECT member_id, loan_id, loan_date,
       COUNT(*) OVER (PARTITION BY member_id ORDER BY loan_date
                       ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_borrow_count
FROM loans
ORDER BY member_id, loan_date;
```

## **6. Second most prolific author per country, no LIMIT/OFFSET**

_Pattern:_ "Nth per group" → DENSE_RANK partitioned by group.  
_Approach:_ Count books per author, rank descending within `country`, filter rank = 2. Using `DENSE_RANK()` here matters — if two authors tie for most books, `RANK()` would skip straight to 3, and you'd miss a legitimate "2nd place."

```sql
WITH author_book_counts AS (
  SELECT a.author_id, a.name, a.country, COUNT(*) AS book_count
  FROM authors a
  JOIN books b ON b.author_id = a.author_id
  GROUP BY a.author_id, a.name, a.country
),
ranked AS (
  SELECT *, DENSE_RANK() OVER (PARTITION BY country ORDER BY book_count DESC) AS rnk
  FROM author_book_counts
)
SELECT country, author_id, name, book_count
FROM ranked
WHERE rnk = 2;
```

## **7. Members with above-average loan duration**

_Pattern:_ multi-level aggregation (compare group aggregate to grand aggregate) → CTE chain + scalar subquery.  
_Approach:_ First compute duration per loan (only for returned loans — return_date is NULL otherwise, so filter those out first or the date math breaks). Then average per member, then compare to the platform-wide average.

```sql
WITH loan_durations AS (
  SELECT member_id, loan_id, (return_date - loan_date) AS duration_days
  FROM loans
  WHERE return_date IS NOT NULL
),
member_avg AS (
  SELECT member_id, AVG(duration_days) AS avg_duration
  FROM loan_durations
  GROUP BY member_id
)
SELECT member_id, avg_duration
FROM member_avg
WHERE avg_duration > (SELECT AVG(duration_days) FROM loan_durations);
```

## **8. Month-over-month % change in new loans issued**

_Pattern:_ period-over-period comparison → LAG().  
_Approach:_ Collapse loans to a monthly count by `loan_date`, then `LAG()` the prior month's count into the same row, guard divisor with `NULLIF`.

```sql
WITH monthly_loans AS (
  SELECT DATE_TRUNC('month', loan_date) AS month, COUNT(*) AS loan_count
  FROM loans
  GROUP BY DATE_TRUNC('month', loan_date)
)
SELECT month, loan_count,
       LAG(loan_count) OVER (ORDER BY month) AS prev_month,
       ROUND(100.0 * (loan_count - LAG(loan_count) OVER (ORDER BY month))
             / NULLIF(LAG(loan_count) OVER (ORDER BY month), 0), 2) AS pct_change
FROM monthly_loans
ORDER BY month;
```

## **9. Books with avg rating < 3 but > 8 reviews**

_Pattern:_ condition on aggregated values → HAVING, single group-by pass with compound condition.  
_Approach:_ One aggregation, two thresholds in HAVING — no CTE needed.

```sql
SELECT b.book_id, b.title, AVG(r.rating) AS avg_rating, COUNT(*) AS review_count
FROM books b
JOIN reviews r ON r.book_id = b.book_id
GROUP BY b.book_id, b.title
HAVING AVG(r.rating) < 3 AND COUNT(*) > 8;
```

## **10. Author pairs frequently borrowed by the same member**

_Pattern:_ relationship between rows in the same table → self-join with inequality to dedupe. The twist: instead of self-joining `order_items`/`loans` directly on order_id, here the "grouping key" for pairing is the _member_, and what we're pairing is _authors_ — so we need to go loans → books → authors first to get a (member, author) table, then self-join that on member_id.

_Approach:_ Build an intermediate view of distinct (member, author) combinations first — otherwise a member borrowing the same author's book 5 times would inflate pair counts. Then self-join that on `member_id` with `a.author_id < b.author_id`.

```sql
WITH member_authors AS (
  SELECT DISTINCT l.member_id, b.author_id
  FROM loans l
  JOIN books b ON b.book_id = l.book_id
)
SELECT a.author_id AS author_a, b.author_id AS author_b, COUNT(*) AS shared_members
FROM member_authors a
JOIN member_authors b ON a.member_id = b.member_id AND a.author_id < b.author_id
GROUP BY a.author_id, b.author_id
ORDER BY shared_members DESC;
```

The `DISTINCT` in the CTE is the key subtlety here — without it, a member who loaned 3 books by Author X and 2 by Author Y would generate 6 (X,Y) pairs from that member alone, wildly overcounting "frequency of co-borrowing" versus what you actually want to measure: how many _members_ connect two authors.
