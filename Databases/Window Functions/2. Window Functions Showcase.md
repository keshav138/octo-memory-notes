Window functions in SQL perform calculations across a set of rows related to the current row, without collapsing them into a single output row (unlike `GROUP BY` aggregates). They "look through a window" of rows defined by an `OVER()` clause.

**Basic syntax:**

```sql
function_name() OVER (
    [PARTITION BY column]
    [ORDER BY column]
    [ROWS/RANGE frame_clause]
)
```

## Sample table: `employees`

|name|department|salary|
|---|---|---|
|Alice|Sales|90000|
|Bob|Sales|85000|
|Carol|Sales|85000|
|Dave|Sales|70000|
|Eve|Eng|120000|
|Frank|Eng|110000|
|Grace|Eng|95000|

---

### 1. Ranking functions

```sql
SELECT name, department, salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS row_num,
    RANK()       OVER (PARTITION BY department ORDER BY salary DESC) AS rank,
    DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dense_rank
FROM employees;
```

|name|department|salary|row_num|rank|dense_rank|
|---|---|---|---|---|---|
|Eve|Eng|120000|1|1|1|
|Frank|Eng|110000|2|2|2|
|Grace|Eng|95000|3|3|3|
|Alice|Sales|90000|1|1|1|
|Bob|Sales|85000|2|2|2|
|Carol|Sales|85000|3|2|2|
|Dave|Sales|70000|4|4|3|

Notice Bob and Carol tie at 85000: `ROW_NUMBER` still gives them different numbers (2,3), `RANK` gives them the same rank (2) but then skips to 4 for Dave, `DENSE_RANK` gives them the same rank (2) and Dave gets 3 with no gap.

**Top-3-per-department query** on this data would return everyone except Dave (since Sales only has Alice, Bob, Carol in the top 3, and Eng has just 3 people total).

### 2. Aggregate functions as window functions

```sql
SELECT name, department, salary,
    SUM(salary)  OVER (PARTITION BY department) AS dept_total,
    AVG(salary)  OVER (PARTITION BY department) AS dept_avg,
    COUNT(*)     OVER (PARTITION BY department) AS dept_headcount
FROM employees;
```

|name|department|salary|dept_total|dept_avg|dept_headcount|
|---|---|---|---|---|---|
|Eve|Eng|120000|325000|108333|3|
|Frank|Eng|110000|325000|108333|3|
|Grace|Eng|95000|325000|108333|3|
|Alice|Sales|90000|330000|82500|4|
|Bob|Sales|85000|330000|82500|4|
|Carol|Sales|85000|330000|82500|4|
|Dave|Sales|70000|330000|82500|4|

Every row keeps its own salary, but also shows the department's total/average — a plain `GROUP BY` would have collapsed this to just 2 rows (one per department).

### 3. Offset functions

Sample table: `daily_sales`

|order_date|revenue|
|---|---|
|2026-09-01|1000|
|2026-09-02|1200|
|2026-09-03|900|
|2026-09-04|1500|

```sql
SELECT order_date, revenue,
    LAG(revenue, 1)  OVER (ORDER BY order_date) AS prev_day_revenue,
    LEAD(revenue, 1) OVER (ORDER BY order_date) AS next_day_revenue,
    revenue - LAG(revenue, 1) OVER (ORDER BY order_date) AS day_over_day_change
FROM daily_sales;
```

|order_date|revenue|prev_day_revenue|next_day_revenue|day_over_day_change|
|---|---|---|---|---|
|2026-09-01|1000|NULL|1200|NULL|
|2026-09-02|1200|1000|900|200|
|2026-09-03|900|1200|1500|-300|
|2026-09-04|1500|900|NULL|600|

First row has no previous day → `NULL`. Last row has no next day → `NULL`.

### 4. Running totals / moving averages

```sql
SELECT order_date, revenue,
    SUM(revenue) OVER (ORDER BY order_date 
                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total,
    AVG(revenue) OVER (ORDER BY order_date 
                        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg_3day
FROM daily_sales;
```

(using a 3-day window here instead of 7 since the sample only has 4 rows)

|order_date|revenue|running_total|moving_avg_3day|
|---|---|---|---|
|2026-09-01|1000|1000|1000|
|2026-09-02|1200|2200|1100|
|2026-09-03|900|3100|1033|
|2026-09-04|1500|4600|1200|

`running_total` accumulates all prior rows + current. `moving_avg_3day` only looks at the current row plus 2 preceding — on day 3, it averages (1000+1200+900)/3; on day 4, the window slides and drops day 1, averaging (1200+900+1500)/3.

### 5. Distribution functions

```sql
SELECT name, salary,
    NTILE(4) OVER (ORDER BY salary) AS salary_quartile,
    PERCENT_RANK() OVER (ORDER BY salary) AS percentile
FROM employees;
```

|name|salary|salary_quartile|percentile|
|---|---|---|---|
|Dave|70000|1|0.00|
|Bob|85000|1|0.17|
|Carol|85000|2|0.33|
|Alice|90000|2|0.50|
|Grace|95000|3|0.67|
|Frank|110000|3|0.83|
|Eve|120000|4|1.00|

`NTILE(4)` splits the 7 rows as evenly as possible into 4 buckets (some buckets get 1 row, some 2). `PERCENT_RANK()` shows where each row sits relative to the whole set — `(rank - 1) / (total_rows - 1)`.
