Here's the common set, roughly from simplest to most sophisticated:

## 1. CLS Token Pooling

A special `[CLS]` token is prepended to the input before encoding. After passing through the transformer, that token's final vector is treated as the whole sequence's representation — everything else is discarded.

```
[CLS] The cat sat on the mat . → take only [CLS]'s output vector
```

- Used by: original BERT, many encoder-only models
- Relies entirely on training the model so that `[CLS]` actually learns to aggregate meaning (via next-sentence-prediction or similar objectives). If the model wasn't trained with that objective, raw `[CLS]` pooling performs poorly.

## 2. Mean Pooling

Average all token vectors element-wise (excluding padding tokens, using an attention mask).

```
chunk_vector = (v1 + v2 + ... + vn) / n
```

- Used by: most `sentence-transformers` models (e.g., `all-MiniLM-L6-v2`, `all-mpnet-base-v2`)
- Generally outperforms CLS pooling for semantic similarity tasks in practice, especially when the base model wasn't specifically trained with a CLS-aggregation objective — it doesn't rely on one token "learning" to summarize, so it's more robust out-of-the-box.

## 3. Max Pooling

Take the element-wise maximum across all token vectors — for each of the 768 (or whatever) dimensions, pick the highest value seen across all tokens.

```
chunk_vector[i] = max(v1[i], v2[i], ..., vn[i])  for each dimension i
```

- Captures the "most salient" activation per feature dimension rather than an average
- Less commonly used for sentence embeddings; more common in older CNN-based text models

## 4. Last-Token Pooling

Take only the final token's hidden state.

- Used by: decoder-only / causal models used as embedders (e.g., some GPT-based embedding setups, LLaMA-based embedders)
- Works because causal attention means each token can only attend to _previous_ tokens — so the last token is the only one that has "seen" the entire sequence. This is why last-token pooling makes sense specifically for causal/decoder architectures but would be meaningless for encoder models where every token sees every other token anyway.

## 5. Weighted Mean Pooling

Like mean pooling, but tokens get different weights instead of equal averaging — commonly weighted by position (later tokens weighted more, since they carry more accumulated context in some architectures) or by attention scores.

## 6. Attention Pooling (learned pooling)

Instead of a fixed rule (mean/max/last), train a small additional layer that learns to assign importance weights to each token dynamically, then computes a weighted sum. Essentially a lightweight attention mechanism sitting on top of the base model's output, trained end-to-end for the embedding task.

- More expressive than fixed pooling but adds extra trainable parameters and complexity

## 7. No Pooling — Multi-Vector Retrieval

Skip collapsing entirely; keep all token-level vectors per chunk. At query time, do fine-grained token-to-token comparison instead of comparing single pooled vectors.

- Used by: ColBERT and similar "late interaction" retrieval models
- Much better retrieval precision (captures word-level matches a single pooled vector would blur away) but significantly more expensive to store and search, since you're storing N vectors per chunk instead of 1

---

**In practice**, for most RAG pipelines you'll encounter mean pooling (sentence-transformers ecosystem) or last-token pooling (if using a decoder-only LLM as your embedder, which is increasingly common with models like `text-embedding-3` or `NV-Embed`). CLS pooling shows up mainly in older or BERT-derivative setups. The choice isn't arbitrary — it's tied to how the specific embedding model was trained, so you generally use whatever pooling method the model's authors trained/validated it with, rather than picking one independently.
