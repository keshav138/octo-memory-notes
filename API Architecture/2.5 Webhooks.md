A webhook is an automated, event-driven HTTP callback. Instead of a client constantly polling an API to check if something changed ("polling"), the server automatically pushes data via an HTTP POST request to a preconfigured URL the instant a specific event occurs ("pushing").

  

**30-Second Interview Script**

  

> "Think of a webhook as a reverse API. With a traditional API, you constantly ask the server, _'Is there an update yet?'_ With a webhook, you give the provider a URL endpoint and say, _'Don't make me ask—just send an HTTP POST request the moment something happens.'_
> 
>   
> 
> A common example is Stripe: instead of polling Stripe every five seconds to see if a customer paid, Stripe triggers a webhook to my server's `/webhooks/payment` route with the payment payload the millisecond it succeeds."
> 
>   

**Key Technical Points to Mention if Probed**

  

- **Architecture:** Inversion of control—your system acts as the server listening on a public route, while the third-party provider acts as the client.
    
      
    
- **Efficiency:** Eliminates the network and compute overhead of high-frequency polling.
    
      
    
- **Reliability & Idempotency:** Webhooks can fail or retry. Robust webhook receivers must verify signatures (e.g., via HMAC secrets) and handle duplicate events idempotently.
