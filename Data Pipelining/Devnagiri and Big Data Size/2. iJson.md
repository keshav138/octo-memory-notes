If you're working with **very large JSON files** (like the one you showed earlier that caused a `MemoryError`), then **`ijson`** is probably the single most important library to learn. It lets you process a JSON file **incrementally**, without loading the whole thing into RAM.

Think of it as the JSON equivalent of reading a huge text file line by line.

---

# Why do we need ijson?

Suppose you have

```
data.json
```

whose size is

```
18 GB
```

Using the normal library:

```python
import json

with open("data.json") as f:
    data = json.load(f)
```

Python tries to build the **entire object in memory**.

```
Disk
 │
 ▼
Entire JSON
 │
 ▼
RAM
 │
 ▼
Python Object
```

If your RAM is

```
16 GB
```

and the JSON expands to

```
30 GB
```

↓

```
MemoryError
```

---

`ijson` never does this.

Instead it reads

```
Disk
 │
 ▼
Tiny chunk
 │
Process
 │
Discard
 │
Next chunk
```

RAM stays almost constant.

# How ijson works

Imagine your JSON is

```json
[
    {"name":"A"},
    {"name":"B"},
    {"name":"C"}
]
```

Normal json

```
Reads

[
 A
 B
 C
]

↓

Creates

list

↓

Returns
```

ijson

```
Reads [

Reads first object

↓

Returns object

Reads second

↓

Returns object

Reads third

↓

Returns object

Done
```

It never stores all three.

# Most important function

```
ijson.items()
```

This is what you'll use 90% of the time.

Example

```python
import ijson

with open("data.json", "rb") as f:

    for item in ijson.items(f, "item"):

        print(item)
```

Suppose

```json
[
 {"a":1},
 {"a":2},
 {"a":3}
]
```

Iteration becomes

Iteration 1

```python
{"a":1}
```

Iteration 2

```python
{"a":2}
```

Iteration 3

```python
{"a":3}
```

Exactly like reading CSV rows.

```json

 {}
]
```

The root object is

```
Array
```

Each element inside is called

```

```

Hence


means

```

```

```
 obj3
]
```

returns

```

obj3
```

# Processing huge files

Suppose

```
50 million objects
```

Don't store them.

Instead

```python
for item in ijson.items(f,"item"):

    process(item)
```

After

```
process()
```

returns,

that object is garbage collected.

Memory remains tiny.

# Reading nested arrays

Suppose

```json
[
  {
      "pages":[
           {
              "text":"A"
           },
           {
              "text":"B"
           }
      ]
  }
]
```

You can do

```python
for doc in ijson.items(f,"item"):

    for page in doc["pages"]:

        print(page["text"])
```

The outer object is streamed.

Inner list is normal Python.

# Lower-level parsing

`ijson` also exposes the raw parsing events:

```python
for prefix, event, value in ijson.parse(f):
    print(prefix, event, value)
```

For this JSON:

```json
{
  "name": "Ram",
  "age": 20
}
```

you'll see events like:

```
 start_map
 map_key name
name string Ram
 map_key age
age number 20
 end_map
```

This is useful when you need very fine-grained control or the JSON structure is unusual, but it's much lower level than `items()`.

# Common functions

## `ijson.items()`

Returns complete objects.

```python
for obj in ijson.items(f,"item"):
```

Most common.

---

## `ijson.kvitems()`

Returns key-value pairs from an object.

Example

```json
{
   "a":1,
   "b":2
}
```

returns

```
("a",1)

("b",2)
```

Useful when the keys themselves are dynamic.

---

## `ijson.parse()`

Lowest level.

Returns parsing events.

Used for custom parsers.

# Performance

`ijson` is:

- Much lower memory than `json.load()`.
    
- Slightly slower because it parses incrementally.
    
- Usually fast enough that disk I/O becomes the bottleneck.
    

---

# Binary mode matters

Always prefer:

```python
with open("data.json", "rb") as f:
```

instead of:

```python
open("data.json")
```

`ijson` works most efficiently with binary file objects.

---

# Common mistakes

### 1. Using `json.load()` first

```python
data = json.load(f)
```

This defeats the purpose of streaming.

---

### 2. Appending everything

Bad:

```python
all_docs = []

for item in ijson.items(f,"item"):
    all_docs.append(item)
```

You've just recreated the memory problem.

Instead:

```python
for item in ijson.items(f,"item"):
    process(item)
```

---

### 3. Wrong path

If your JSON starts with:

```json
{
   "documents":[ ... ]
}
```

this is wrong:

```python
ijson.items(f,"item")
```

Correct:

```python
ijson.items(f,"documents.item")
```

Always match the path to the structure of the JSON.

---

# When to use ijson

Use it when:

- The JSON file is too large to fit comfortably in RAM.
    
- You want to process one object at a time.
    
- You're extracting, filtering, or transforming records.
    

Stick with the standard `json` library when:

- The file is small (a few MB).
    
- You need random access to many parts of the JSON after loading it.
    
- Simplicity is more important than streaming.

## For your specific use case

From the screenshot you shared earlier, your file appears to be a **large top-level JSON array** where each element represents a scraped document with fields such as `link`, `page_number` (or similar), and nested text data.

That means your main processing loop will likely look like this:

```python
import ijson

with open("large.json", "rb") as f:
    for document in ijson.items(f, "item"):
        # Access metadata
        link = document.get("link")
        page = document.get("page_number")

        # Process nested content
        thread = document.get("page_thread", [])
        # ...extract text, create embeddings, write output, etc.
```

This pattern scales to millions of documents because only one document is held in memory at a time, making it ideal for preprocessing large corpora before tokenization, embedding generation, or model training.
