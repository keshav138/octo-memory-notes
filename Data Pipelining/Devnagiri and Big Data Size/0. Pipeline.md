## Team split 

**1. Data pipeline **

- Stream-parse the 22GB JSON (don't load it all into memory — use `ijson` or line-by-line if it's JSONL, or `json.load` per-document if it's an array you can chunk)
- Extract `text_data` fields only, drop `_id`/`link`
- Clean: strip OCR noise (the sample shows garbled fragments like `"$5911001 19०."`), normalize Unicode (Devanagari has multiple encodings for the same glyph — normalize with `unicodedata.normalize('NFC', ...)`), dedupe pages, filter out non-Nepali/low-quality pages
- Subsample down to a workable size (~1-2GB) with decent topic diversity, split train/val (95/5)

**2. Tokenizer **

- Train a SentencePiece BPE tokenizer _from your own corpus_ — don't reuse GPT-2's English BPE, it fragments Devanagari badly
- Vocab size ~16k-32k is enough for this scale

**3. Model + training**

- Base off nanoGPT (Karpathy's repo) — small, readable, well-suited to single-GPU training, easy to shrink config (n_layer=6-8, n_embd=384-512, n_head=6-8 → ~15-40M params)
- Mixed precision (fp16/bf16), gradient accumulation to fake a bigger batch size
- **Checkpoint to Google Drive every N steps** — this is non-negotiable given Colab disconnects, or you lose runs
- Split further: one person owns training loop, one owns config/hyperparameter sweeps, one owns getting it running reliably across disconnects

**4. Evaluation **

- Track train/val loss + perplexity
- Qualitative: generate samples at checkpoints, track coherence improving over training
- Optional: simple intrinsic eval like masked-word prediction accuracy on held-out text

**5. Integration + writeup**

- Merge everyone's code into one clean repo/notebook
- Report: data pipeline decisions, tokenizer stats, architecture choices, loss curves, sample generations, what you'd do with more compute
- Presentation/demo prep
