Deduplication is one of the most impactful preprocessing steps for LLM training. If your corpus contains many duplicates, the model wastes training time memorizing the same content instead of learning new patterns.

For scraped PDFs, websites, or OCR documents, duplicates are extremely common.

---

# Why Deduplicate?

Imagine you scraped 1 million documents.

Your dataset looks like

```text
Document 1
राम घर गया।

Document 2
राम घर गया।

Document 3
राम घर गया।

Document 4
भारत की राजधानी नई दिल्ली है।
```

Without deduplication

```
Training Data

50% identical text

↓

Model repeatedly sees same sentence

↓

Less diverse learning
```

The model becomes biased toward repeated documents.

---

# Types of Duplicates

There are three major categories.

```
Duplicate Documents

├── Exact Duplicate
├── Near Duplicate
└── Partial Duplicate
```

---

# 1. Exact Duplicate

The easiest case.

```
Doc A

राम घर गया।
```

```
Doc B

राम घर गया।
```

Byte-for-byte identical.

---

Example

```
PDF Download 1

↓

Document
```

```
PDF Download 2

↓

Same Document
```

Different filenames.

Same content.

---

## Detecting Exact Duplicates

The easiest method is hashing.

```
Document

↓

SHA256

↓

Unique fingerprint
```

Example

```python
import hashlib

text = "राम घर गया।"

hash_value = hashlib.sha256(text.encode("utf-8")).hexdigest()
```

Produces something like

```
6f8e3...
```

If another document has the same hash

```
Same hash

↓

Duplicate
```

---

Implementation

```python
seen = set()

for doc in documents:

    h = hashlib.sha256(doc.encode()).hexdigest()

    if h in seen:
        continue

    seen.add(h)
```

Memory usage

```
Only hashes stored

Not entire documents
```

---

# MD5 vs SHA256

People often ask which to use.

For deduplication

```
MD5

or

SHA256

Both work
```

SHA256 has far fewer collision concerns.

# 2. Near Duplicates

Much harder.

Example

Document A

```
राम घर गया।
उसने खाना खाया।
```

Document B

```
राम घर गया।
उसने भोजन किया।
```

Not identical.

Almost the same meaning.

---

Or

```
Extra spaces

↓

Different line breaks

↓

Small OCR mistakes
```

Normal hashes fail.

---

# Solution: Normalize First

```
Raw Text

↓

Unicode NFC

↓

Whitespace cleanup

↓

Lowercase (for languages that have case)

↓

Hash
```

Now many duplicates become exact duplicates.

---

Example

Before

```
राम     घर गया।
```

After

```
राम घर गया।
```

Now hashes match.

# SimHash

A famous algorithm.

Idea

```
Document

↓

64-bit fingerprint

↓

Similar documents

↓

Fingerprints differ only slightly
```

Example

```
Doc A

10101100...
```

```
Doc B

10101101...
```

Only one bit differs.

Likely duplicate.

---

Advantages

```
Very fast

Very little memory
```

Used by search engines.

# MinHash

Very common in LLM preprocessing.

Idea

```
Document

↓

Split into shingles

↓

Hash shingles

↓

Estimate similarity
```

---

Suppose

```
राम घर गया।

उसने खाना खाया।
```

Shingles

```
राम घर

घर गया

गया उसने

उसने खाना

खाना खाया
```

Compare overlap.

---

Similarity

```
Intersection

/

Union
```

This approximates the Jaccard similarity.

---

# Jaccard Similarity

Suppose

Document A

```
A B C D
```

Document B

```
A B D E
```

Intersection

```
A B D
```

=

3

Union

```
A B C D E
```

=

5

Similarity

```
3 / 5

=

0.6
```

If

```
Similarity > 0.9
```

Remove duplicate.

Instead of words,

take sequences.

Example

```

```

2-word shingles

```

गया आज
```

Documents with many identical shingles

↓

# Locality Sensitive Hashing (LSH)

Comparing every document with every other document is infeasible.

```
1 million docs

↓

10^12 comparisons
```

Too expensive.

LSH narrows comparisons.

```
Document

↓

Signature

↓

Bucket

↓

Compare only within bucket
```

This reduces work dramatically.

# Streaming Deduplication

Works perfectly with `ijson`.

```python
import hashlib
import ijson

seen = set()

with open("data.json", "rb") as f:

    for item in ijson.items(f, "item"):

        text = item["text"]

        h = hashlib.sha256(text.encode("utf-8")).hexdigest()

        if h in seen:
            continue

        seen.add(h)

        process(text)
```

Memory stays low because only hashes are retained.

---

# Memory Considerations

Suppose

```
10 million documents
```

A SHA256 hash is 32 bytes.

Ignoring Python object overhead:

```
10,000,000 × 32 bytes

≈ 320 MB
```

In practice, a Python `set` uses substantially more memory (often 2–4× or more due to object and table overhead), so for tens of millions of documents you may need several gigabytes of RAM. At that scale, consider disk-backed databases, Bloom filters (for approximate membership), or distributed processing.

# Deduplication Order

A good pipeline is

```
Raw Text
      │
      ▼
Unicode NFC
      │
      ▼
OCR Cleaning
      │
      ▼
Whitespace Cleanup
      │
      ▼
Deduplication
      │
      ▼
Tokenizer Training
```

Always clean **before** hashing. Otherwise these two texts:

```
राम     घर गया।
```

and

```
राम घर गया।
```

produce different hashes even though they should be treated as the same.

---

# What Large LLM Projects Do

Large-scale training pipelines (such as those used for modern open-source LLMs) generally combine several techniques:

```
Raw Corpus
      │
      ▼
Exact Deduplication (SHA256/MD5)
      │
      ▼
Near-Duplicate Detection (MinHash + LSH)
      │
      ▼
Quality Filtering
      │
      ▼
Tokenizer Training
      │
      ▼
Model Training
```

Exact hashing removes identical copies almost for free. Near-duplicate detection catches pages that differ only by formatting, OCR noise, or minor edits.

# For Your Hindi Decoder Project

Given your large streamed JSON dataset, a practical and effective approach would be:

1. Stream documents using `ijson`.
    
2. Extract the text.
    
3. Apply Unicode NFC normalization.
    
4. Perform OCR cleaning and whitespace normalization.
    
5. Compute a SHA-256 hash of the cleaned text.
    
6. Skip documents whose hash has already been seen.
    
7. Save the unique cleaned documents for tokenizer training.
    

Once you move from a small educational model to a larger corpus (millions of documents), the next upgrade would be to replace exact hashing alone with **MinHash + LSH** so you can also eliminate near-duplicate documents efficiently. That combination is the standard approach in large-scale LLM data pipelines.
