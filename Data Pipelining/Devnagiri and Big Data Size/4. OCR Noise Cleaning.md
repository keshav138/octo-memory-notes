OCR cleaning is one of the most important preprocessing stages when training an LLM on scanned books or PDFs. Good OCR cleaning can significantly improve tokenizer quality and reduce wasted vocabulary.

Think of the complete pipeline like this:

```text
PDF
 │
 ▼
OCR
 │
 ▼
Noisy Text
 │
 ▼
OCR Cleaning
 │
 ▼
Normalized Text
 │
 ▼
Tokenizer
 │
 ▼
LLM Training
```

# What is OCR Noise?

OCR (Optical Character Recognition) converts images into text.

Unfortunately, OCR is imperfect.

Suppose the original page says

```text
राम घर गया।
```

OCR might produce

```text
राम घर गय।।
```

or

```text
राम घर गया |
```

or

```text
राm घर गया।
```

The LLM would treat all of these as different text.

---

# Types of OCR Noise

## 1. Character Substitution

One character becomes another.

Example

```text
Original

भारत
```

OCR

```text
भारत
```

or

```text
भारत
```

English examples

```text
Original

Hello
```

OCR

```text
He11o
```

where

```text
l

↓

1
```

---

## 2. Missing Characters

```text
Original

विद्यालय
```

OCR

```text
विदयालय
```

One letter disappears.

---

## 3. Extra Characters

```text
राम
```

↓

```text
रााम
```

---

## 4. Broken Words

OCR sometimes inserts spaces.

```text
Original

विद्यालय
```

↓

```text
विद्या लय
```

Tokenizer now sees two words.

---

## 5. Merged Words

```text
राम घर
```

↓

```text
रामघर
```

---

## 6. Line Break Artifacts

Books often wrap lines.

Original

```text
भारत का इतिहास
बहुत विशाल है।
```

OCR

```text
भारत का इतिहास
बहुत विशाल है।
```

If joined incorrectly:

```text
इतिहासबहुत
```

or

```text
इतिहास-
बहुत
```

---

## 7. Hyphenation

Printed books split words.

```text
inter-
national
```

OCR keeps

```text
inter-
national
```

Correct preprocessing joins it

```text
international
```

---

## 8. Header/Footer Noise

Every page

```text
Page 24
```

or

```text
CHAPTER 3
```

gets repeated.

Tokenizer learns useless tokens.

---

## 9. Page Numbers

```text
125
```

appears every page.

Usually removed.

---

## 10. Random Symbols

OCR loves inventing characters.

```text
§
¤
¦
©
~
```

They often aren't in the source.

---

## 11. Encoding Problems

Sometimes

```text
�
```

appears.

This is the Unicode replacement character.

Usually remove it.

---

## 12. Mixed Scripts

OCR may mix Latin and Devanagari.

```text
राm
```

instead of

```text
राम
```

or

```text
O
```

instead of

```text
०
```

A common order is:

```text

      ▼

      │

      │
      ▼
Fix hyphenation
      │
      ▼
Remove headers/footers
      │
      ▼

      │

      ▼
```

# Unicode Cleaning

Remove replacement characters.

```python
text = text.replace("\uFFFD", "")
```

# Whitespace Normalization

OCR often generates

```text
राम     घर
```

Normalize

```python
import re

text = re.sub(r"\s+", " ", text)
```

Result

```text
राम घर
```


```python
re.sub(r"^भारत का संविधान$", "", text, flags=re.MULTILINE)
```

# Remove Control Characters

Characters like

```text
\x00
\x01
\x02
```

should disappear.

```python
''.join(c for c in text if c.isprintable())
```

# Regex Cleaning

Suppose OCR produced

```text
राम@@@घर###
```

Regex

```python
re.sub(r"[@#]+", "", text)
```

↓

```text
रामघर
```

# Detect Garbage Lines

Suppose OCR outputs

```text
@#$%%^^
```

You can discard lines with very few letters.

Example heuristic

```python
letters = sum(c.isalpha() for c in line)

if letters < 3:
    continue
```

---

# Remove Duplicate Pages

Some PDFs contain duplicate scans.

Hash every cleaned page.

```python
hash(text)
```

Keep only unique hashes.

---

# Language Filtering

Suppose English OCR accidentally enters Hindi corpus.

You may discard pages that contain too few Devanagari characters.

Example heuristic

```text
If <30% characters are Hindi

↓

Discard
```

# Remove Repeated Characters

OCR

```text
राआआम
```

Regex

```python
re.sub(r"(.)\1{3,}", r"\1", text)
```

↓

```text
राम
```

Be careful—this can be wrong for legitimate repeated characters in some languages.

# Should You Lowercase?

English

```text
Apple

↓

```

Sometimes useful.

Hindi

No lowercase exists.

So do **not** lowercase Hindi—it has no effect.

# A Realistic OCR Cleaning Function

```python
import re
import unicodedata

def clean_text(text):
    # Unicode normalization
    text = unicodedata.normalize("NFC", text)

    # Remove replacement characters
    text = text.replace("\uFFFD", "")

    # Normalize whitespace
    text = re.sub(r"\s+", " ", text)

    # Remove empty lines
    text = re.sub(r"\n\s*\n+", "\n", text)

    return text.strip()
```

You can call this for every document yielded by `ijson`.

# How This Fits Into Your LLM Pipeline

For the Hindi decoder model you're building, the preprocessing flow would typically be:

```text
Large JSON (ijson)
        │
        ▼
Extract page text
        │
        ▼
Unicode NFC normalization
        │
        ▼
OCR cleaning
        │
        ▼
Whitespace normalization
        │
        ▼
Remove headers/footers & page numbers
        │
        ▼
(Optional) Filter poor-quality pages
        │
        ▼
Train tokenizer
        │
        ▼
Tokenize corpus
        │
        ▼
Train decoder model
```

One important guideline: **be conservative**. It's generally safer to leave a few OCR mistakes in the corpus than to apply aggressive cleaning rules that accidentally alter valid words or sentences. The model can often learn around occasional noise, but systematic over-cleaning can permanently remove useful information.
